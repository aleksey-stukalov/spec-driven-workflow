# Why

Use the clearer directory name `agentic_harness/` requested by the user for the
distributed workflow and its documented commands. Preserve existing consumer
installations and historical evidence while changing this public package path.

# What Changes

- Rename the package directory and all current commands, integrations and checks.
- Generate the handbook with the new paths.
- Upgrade verified legacy installations through the existing transactional plan,
  retaining local configuration, stable identities and unowned files.
- Read historical privacy exclusions at their original immutable paths.
- Keep archived change records and original GitBob provenance truthful.

# Capabilities

## Modified Capabilities

- `harness-configuration`: canonical package location and safe legacy-directory upgrade.

# Impact

The installer, runtime path selection, evidence capture, adapters, tests, CI and
current documentation use the new path. Existing scripts invoking the old path
must use the new command after an upgrade. Native OpenSpec-generated integrations,
application configuration and GitBob remain unchanged. Active runs retain their
original runtime/worktree rather than being migrated in place.
